我们现在将实现一个简单的性能评估脚本。我们将测试模型的许多变体（更改精度、交换层等），因此让你的脚本通过命令行参数启用这些变体以使它们稍后易于运行是值得的。

首先，让我们通过计时前向传播、反向传播和优化器步骤来对模型进行最简单的分析。由于我们仅测量速度和内存，因此可以使用随机权重和数据。

衡量绩效是很微妙的——一些常见的陷阱可能会导致我们无法衡量我们想要的东西。对于 GPU 代码 benchmarking，需要注意的是 CUDA 调用是异步的。当你调用 CUDA kernel 时，例如调用 torch.matmul 时，PyTorch 函数调用会将控制权返回给你的代码，而无需等待矩阵乘法完成。这样，CPU 可以继续提前运行并调度新的运算，同时 GPU 完成矩阵乘法，这是性能的重大提升。另一方面，这意味着直接测量 torch.matmul 调用需要多长时间才能返回并不能告诉我们 GPU 实际运行矩阵乘法需要多长时间。在 PyTorch 中，我们可以调用 torch.cuda.synchronize() 来等待所有调度的 GPU kernel 完成，从而使我们能够更准确地测量 CUDA kernel 运行时间。该操作中的同步是指 CPU 运行时与 GPU 运行时同步。考虑到这一点，让我们编写基本的分析基础设施。

2.1.4 Nsight Systems Profiler

端到端 benchmarking 并不能告诉我们模型在前向和反向传播过程中花费了时间和内存，因此也没有暴露具体的优化机会。要了解我们的程序在每个组件（例如函数）上花费了多少时间，我们可以使用 profiler。执行 profiler 通过在函数开始和完成运行时插入防护来检测代码，从而可以提供函数级别的详细执行统计信息（例如调用次数、平均花费多长时间、在此函数上花费的累积时间等）。

标准 Python profiler（例如 cProfile）无法分析 CUDA kernel，因为这些 kernel 在 GPU 上异步执行。幸运的是，NVIDIA 提供了一个 profiler，我们可以通过 CLI nsys 使用它。我们建议你从软件包管理器或使用下载页面的安装程序获取最新版本。在这部分作业中，你将使用 nsys 来分析 Transformer 模型的运行时。

使用 nsys 非常简单：运行上一节中的 Python 脚本，并在前面添加 nsys profile。例如，你可以使用以下命令运行脚本 benchmark.py 的基本 profile：

$ uv run nsys profile -- python benchmark.py

然后，你可以使用以下命令查看本地计算机上的 profile

NVIDIA Nsight Systems 桌面应用程序。在 profile 的 CUDA API 行中选择特定的 CUDA API 调用（在 CPU 上）将突出显示 CUDA HW 行中的所有相应 kernel 执行（在 GPU 上）。

更全面的分析运行可能如下所示：

$ uv run nsys profile --trace=cuda,cudnn,cublas,osrt,nvtx --pytorch=functions-trace,autograd-shapes-nvtx --cudabacktrace=all --python-backtrace=cuda --gpu-metrics-devices=0 -- python benchmark.py

2.1.5 Mixed Precision

到目前为止，我们一直在以 FP32 精度运行——所有模型参数和激活都具有 torch.float32 数据类型。然而，现代 NVIDIA GPU 包含专用 GPU 核心（Tensor Core），用于以较低精度加速矩阵乘法。例如，NVIDIA B200 规格表表示，其 FP32 的最大吞吐量为 80 TFLOPS，而 FP16（半精度浮点）或 BF16 (bfloat16) 的最大吞吐量则明显更高，高达 2500 TFLOPS。因此，使用较低精度的数据类型应该有助于我们加快训练和推理速度。

然而，直接将我们的模型转换为较低精度的格式可能会降低模型的准确性。例如，实践中的许多梯度值通常太小而无法在 FP16 中表示，因此在使用 FP16 精度进行简单训练时会变为零。为了解决这个问题，在使用 FP16 进行训练时，通常会使用损失缩放——损失简单地乘以缩放因子，增加梯度幅度，这样它们就不会冲至零。此外，FP16 的动态范围比 FP32 低，这可能导致溢出，表现为 NaN 损失。完整的 bfloat16 训练通常更稳定（因为 BF16 具有与 FP32 相同的动态范围），但与 FP32 相比，仍然会影响最终模型的性能。

为了利用低精度数据类型的加速优势，通常使用 mixed precision 训练。在 PyTorch 中，这是通过 torch.autocast 上下文管理器实现的。在这种情况下，某些运算（例如矩阵乘法）以较低精度的数据类型执行，而需要 FP32 完整动态范围的其他运算（例如累加和缩减）则保持原样。例如，以下代码将自动识别在前向传播期间以较低精度执行哪些操作，并将这些操作转换为指定的数据类型：

model : torch.nn.Module = ... # e.g. your Transformer model
dtype : torch.dtype = ... # e.g. torch.bfloat16
x : torch.Tensor = ... # input data

with torch.autocast(device_type="cuda", dtype=dtype):
    y = model(x)

如上所述，即使所累加的张量本身已经向下转换，保持累加的精度通常是一个好主意。以下练习将帮助你建立关于为什么会出现这种情况的直觉。

3.1 Autograd 残留张量

回想一下，为了对模型执行反向传播，我们需要保存在前向传播中产生的激活。虽然对于某些操作来说显然是这种情况，但默认情况下，发生这种情况的情况会比你预期的要多得多。为反向传播保存的张量称为“残差”，或简称为“保存的张量”。

让我们对网络中保存的内容有一些了解。从我们不起眼的 RMSNorm 函数（为了简单起见，纯 FP32）开始，让我们为 autograd 保存或检索张量时添加一些钩子。

import torch
from torch import nn

x = torch.randn((4, 512, 2560), requires_grad=True)

class RMSNorm(nn.Module):
    def __init__(
        self,
        hidden_size: int,
        eps: float = 1e-5,
        device=None,
    ):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(hidden_size, device=device))
        self.eps = eps

    def forward(self, x):
        rms = torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)
        x = x * rms
        return self.weight * x

def pack_hook(t):
    shape, dtype, grad_fn = t.shape, t.dtype, t.grad_fn
    print(f"Saving residual: {shape=}, {dtype=}, {grad_fn=}")
    return t

def unpack_hook(t):
    shape, dtype, grad_fn = t.shape, t.dtype, t.grad_fn
    print(f"Loading residual: {shape=}, {dtype=}, {grad_fn=}")
    return t

ln = RMSNorm(x.shape[-1])

with torch.autograd.graph.saved_tensors_hooks(pack_hook, unpack_hook):
    y = ln(x)
    y.sum().backward()

虽然融合无疑很有用，但它在节省内存方面只能让我们到目前为止。例如，让我们融合一个大小为 x1 的 TransformerBlock。

def pack_hook(t):
    if isinstance(t, torch.nn.Parameter):  # Skip logging parameters to avoid double counting

    global total_size_bytes
    shape, dtype, grad_fn = t.shape, t.dtype, t.grad_fn
    total_size_bytes += t.numel() * t.element_size()
    print(f"Saving residual: {shape=}, {dtype=}, {grad_fn=}")
    return t

3.2.1 重计算

可以只保存结果的定期 checkpoint，并重计算中间的值，而不是保留我们生成的每个张量。 PyTorch 有一个接口，我们可以调用它以简单的方式处理这个问题。 torch.utils.checkpoint.checkpoint 接受一个函数以及该函数的参数。然后它修改传递的函数的行为：

  1. 在前向传播中：

  2. 保存函数的输入值

  3. 抑制前向传播中张量的保存

  4. 在反向传播中：

  5. 预先考虑一个重计算步骤，其中前向传播是根据之前保存的输入重计算的，并且值被保存用于反向传播

  6. 运行反向传播并且可以释放所有张量

在运行 4 个 Transformer 块的简单情况下，我们看到内存加起来正如我们预期的那样。

    x = block(x)
    x = block(x)
    x = block(x)
    x = block(x)
    return x

with torch.autograd.graph.saved_tensors_hooks(pack_hook, unpack_hook):
    y = four_blocks(x)

from torch.utils.checkpoint import checkpoint
def two_blocks(x):
    x = block(x)
    x = block(x)
    return x

def four_blocks_checkpoint(x):
    # checkpoint throws out all the saved tensors until the backward pass
    # when getting to the checkpointed block in the backward pass,
    # it reruns a forward pass to produce the saved tensors,
    # then completes normal backward pass.
    x = checkpoint(two_blocks, x, use_reentrant=False)
    x = checkpoint(two_blocks, x, use_reentrant=False)
    return x

with torch.autograd.graph.saved_tensors_hooks(pack_hook, unpack_hook):
    y = four_blocks_checkpoint(x)

print(f"Total size of saved tensors in four TransformerBlocks with checkpointing: {total_size_bytes / (1024**2):.2f} MiB")

请记住，这并没有消除内存使用。相反，它将我们的内存使用分为两类：我们保存的长期存储，以准备在每个 checkpoint 调用的入口点（checkpoint 本身）进行重计算，以及在 checkpoint 块内的重计算过程中生成的短期内存，以方便反向传播。由于我们主要考虑的是峰值内存使用量，因此我们希望平衡已保存 checkpoint 的内存成本与实现完整块残差的内存成本。我们使用的 checkpoint 越多，单个块内的物化内存量就越小，但 checkpoint 本身需要的内存就越多。

在上面的示例中，很明显，重计算的残差内存占主导地位（部分原因是我们的 checkpoint 很小），因此将平衡更多地转向 checkpoint 内存将是有益的。因此，我们希望减小 checkpoint 块的范围。

拥有更大或更小的 checkpoint 块不会影响重计算的计算成本，但我们可以通过使用递归 checkpoint 以计算成本继续减少所需的内存，这意味着我们在其他 checkpoint 调用中进行下一个 checkpoint 调用。

前向传播

def weighted_sum(x, weight):

在编写 Triton kernel 时，我们将让每个程序实例（可能并行运行）计算 x 行 tile 的加权和，并将相应的标量输出写入输出张量。在 Triton 中，程序实例是运行同一程序的线程块，这些线程块可以在 GPU 上并行运行。我们不将张量作为参数，而是将其第一个元素的指针以及每个张量的步幅告诉我们如何沿轴移动。

我们可以使用步幅来加载与我们在运行实例中求和的 x 行 tile 相对应的张量，使用程序 ID 来划分工作（即，实例 i 将处理 x 行的第 i 个 tile）。在这个简单的情况下，Triton 和 PyTorch 中的前向传播之间的主要区别是需要进行指针算术和显式加载/存储。我们将使用 tl.make_block_ptr 的块指针抽象来极大地简化指针运算，尽管这意味着我们需要做一些设置来准备块指针。

import triton
import triton.language as tl

@triton.jit
def weighted_sum_fwd(
    x_ptr, weight_ptr,  # Input pointers
    output_ptr,  # Output pointer
    x_stride_row, x_stride_dim,
    weight_stride_dim,
    output_stride_row,
    NUM_ROWS, D,
    ROWS_TILE_SIZE: tl.constexpr, D_TILE_SIZE: tl.constexpr,
):
    row_tile_idx = tl.program_id(0)
    x_block_ptr = tl.make_block_ptr(
        x_ptr,
        shape=(NUM_ROWS, D),
        strides=(x_stride_row, x_stride_dim),
        offsets=(row_tile_idx * ROWS_TILE_SIZE, 0),
        block_shape=(ROWS_TILE_SIZE, D_TILE_SIZE),
        order=(1, 0),
    )
    weight_block_ptr = tl.make_block_ptr(
        weight_ptr,
        shape=(D,),
        strides=(weight_stride_dim,),
        offsets=(0,),
        block_shape=(D_TILE_SIZE,),
        order=(0,),
    )
    output_block_ptr = tl.make_block_ptr(
        output_ptr,
        shape=(NUM_ROWS,),
        strides=(output_stride_row,),
        offsets=(row_tile_idx * ROWS_TILE_SIZE,),
        block_shape=(ROWS_TILE_SIZE,),
        order=(0,),
    )
    output = tl.zeros((ROWS_TILE_SIZE,), dtype=tl.float32)
    for _ in range(tl.cdiv(D, D_TILE_SIZE)):
        row = tl.load(x_block_ptr, boundary_check=(0, 1), padding_option="zero")
        weight = tl.load(weight_block_ptr, boundary_check=(0,), padding_option="zero")
        output += tl.sum(row * weight[None, :], axis=1)
        x_block_ptr = x_block_ptr.advance((0, D_TILE_SIZE))
        weight_block_ptr = weight_block_ptr.advance((D_TILE_SIZE,))
    tl.store(output_block_ptr, output, boundary_check=(0,))

class WeightedSumFunc(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, weight):
        D, output_dims = x.shape[-1], x.shape[:-1]
        input_shape = x.shape
        x = rearrange(x, "... d -> (...) d")
        ctx.save_for_backward(x, weight)
        assert len(weight.shape) == 1 and weight.shape[0] == D, "Dimension mismatch"
        assert x.is_cuda and weight.is_cuda, "Expected CUDA tensors"
        assert x.is_contiguous(), "Our pointer arithmetic will assume contiguous x"
        ctx.D_TILE_SIZE = triton.next_power_of_2(D) // 16
        ctx.ROWS_TILE_SIZE = 16
        ctx.input_shape = input_shape
        y = torch.empty(output_dims, device=x.device)
        n_rows = y.numel()
        weighted_sum_fwd[(triton.cdiv(n_rows, ctx.ROWS_TILE_SIZE),)](
            x, weight, y,
            x.stride(0), x.stride(1),
            weight.stride(0), y.stride(0),
            NUM_ROWS=n_rows, D=D,
            ROWS_TILE_SIZE=ctx.ROWS_TILE_SIZE,
            D_TILE_SIZE=ctx.D_TILE_SIZE,
        )
        return y.view(input_shape[:-1])

请注意，当我们使用 weighted_sum_fwd[(triton.cdiv(n_rows, ctx.ROWS_TILE_SIZE),)]调用 Triton kernel 时，我们通过传递元组(triton.cdiv(n_rows, ctx.ROWS_TILE_SIZE),)来定义所谓的线程块“启动网格”。然后，我们可以在 kernel 中使用 tl.program_id(0) 访问线程块索引。

反向传播

由于我们正在定义自己的 kernel，因此我们还需要编写自己的后向函数。

在前向传播中，我们获得了该层的输入，并且需要计算其输出。在反向传播中，回想一下，我们将获得目标相对于输出的梯度，并且需要计算相对于每个输入的梯度。在我们的例子中，我们的操作有一个矩阵 $ x : \mathbb{R}^{n \times h} $ 和一个权重向量 $ w : \mathbb{R}^h $ 作为输入。为了简洁起见，我们将我们的操作称为 $ f(x, w) $，其范围为 $ \mathbb{R}^n $。然后，假设我们给出 $ \nabla_{f(x, w)} \mathcal{L} $，即损失 $ \mathcal{L} $ 相对于层输出的梯度，我们可以应用多元链式法则来获得关于 $ x $ 和 $ w $ 的梯度的以下表达式：

\[ \left(\nabla_x \mathcal{L}\right)_{ij} = \sum_{k=1}^{n} \frac{\partial f(x,w)_k}{\partial x_{ij}} \left(\nabla_{f(x,w)} \mathcal{L}\right)_k = w_j \cdot \left(\nabla_{f(x,w)} \mathcal{L}\right)_i \tag{2} \]
\[ \left(\nabla_w \mathcal{L}\right)_j = \sum_{i=1}^{n} \frac{\partial f(x,w)_i}{\partial w_j} \left(\nabla_{f(x,w)} \mathcal{L}\right)_i = \sum_{i=1}^{n} x_{ij} \cdot \left(\nabla_{f(x,w)} \mathcal{L}\right)_i \tag{3} \]

这给出了计算反向传播的简单公式。为了获得相对于 $x$ 的反向步骤，我们应用 $\boxed{\text{Equation 2}}$ 并取 $w$ 和 $\nabla_{f(x,w)}$ 的外积。要计算相对于 $w$（即 $(\nabla_w \mathcal{L})_j$）的反向步骤，我们必须将输入梯度乘以相应的输出行。

我们的反向传播 kernel 将首先定义所有块指针，然后计算 $ \nabla_x \mathcal{L} $：

    n_row_tiles = tl.num_programs(0)

        block_shape=(ROWS_TILE_SIZE, D_TILE_SIZE), order=(1, 0),
    )
    weight_block_ptr = tl.make_block_ptr(
        weight_ptr, shape=(D,), strides=(stride_wd,), offsets=(0,),
        block_shape=(D_TILE_SIZE,), order=(0,),
    )
    grad_x_block_ptr = tl.make_block_ptr(

        offsets=(row_tile_idx * ROWS_TILE_SIZE, 0),
        block_shape=(ROWS_TILE_SIZE, D_TILE_SIZE), order=(1, 0),

    partial_grad_weight_block_ptr = tl.make_block_ptr(

        strides=(stride_gwb, stride_gwd), offsets=(row_tile_idx, 0),
        block_shape=(1, D_TILE_SIZE), order=(1, 0),
    )
    for _ in range(tl.cdiv(D, D_TILE_SIZE)):
        grad_output = tl.load(grad_output_block_ptr, boundary_check=(0,), padding_option="zero")
        weight = tl.load(weight_block_ptr, boundary_check=(0,), padding_option="zero")
        grad_x_row = grad_output[:, None] * weight[None, :]
        tl.store(grad_x_block_ptr, grad_x_row, boundary_check=(0, 1))
        row = tl.load(x_block_ptr, boundary_check=(0, 1), padding_option="zero")
        grad_weight_row = tl.sum(row * grad_output[:, None], axis=0, keep_dims=True)
        tl.store(partial_grad_weight_block_ptr, grad_weight_row, boundary_check=(1,))
        x_block_ptr = x_block_ptr.advance((0, D_TILE_SIZE))
        weight_block_ptr = weight_block_ptr.advance((D_TILE_SIZE,))
        partial_grad_weight_block_ptr = partial_grad_weight_block_ptr.advance((0, D_TILE_SIZE))
        grad_x_block_ptr = grad_x_block_ptr.advance((0, D_TILE_SIZE))

理解朴素 attention 的低效之处

回想一下，attention 的前向传播（暂时忽略掩蔽）可以写成：

$$ \boldsymbol{S}=\boldsymbol{Q}\boldsymbol{K}^{\top}/\sqrt{d} $$

$$ P_{ij}=softmax_{j}\left(S\right)_{ij} $$

$$ O=P V $$

标准的反向传播是

$$ d V=\boldsymbol{P}^{\top}d\boldsymbol{O} $$

$$ d P=d O V^{\top} $$

$$ d S_{i}=\mathrm{dsoftmax}(d P_{i})=\left(\mathrm{diag}(P_{i})-P_{i}P_{i}^{\top}\right)d P_{i} $$

$$ d Q=d S K/\sqrt{d} $$

$$ d\boldsymbol{K}=d\boldsymbol{S}^{\top}\boldsymbol{Q}/\sqrt{d} $$

正如我们所看到的，反向传播依赖于前向传播的一些非常大的激活。例如，计算 $ \text{Equation 7} $ 中的 $ dV $ 需要 $ P $，它们是形状 (batch_size, n_heads, seq_len, seq_len) 的 attention 分数——该激活矩阵的大小与序列长度呈二次方关系，这解释了我们上面在对大序列长度的 attention 进行 benchmarking 时遇到的内存问题。在普通 attention 的前向和反向传播过程中，我们付出了大量的内存 IO 成本来在片上 SRAM 和 GPU HBM 之间传输 $ P $ 和其他大型激活。标准实现中进行了多种此类传输：例如，标准反向传播实现将在 $ \text{Equation 7} $ 和 $ \text{Equation 9} $ 的计算中从 HBM 读取 $ P $。

FlashAttention 的主要目标是避免从 HBM 读取和写入 attention 矩阵，以减少 IO 和峰值内存成本。我们使用三种技术来实现这一点：tiling、重计算和 operator fusion。

分块（tiling）

为了避免在 HBM 中读写 attention 矩阵，我们在不访问整个输入的情况下计算 softmax 缩减。具体来说，我们重构 attention 计算，将输入分割成 tile，并对输入 tile 进行多次传递，从而逐步执行 softmax 缩减。

重计算

我们避免在 HBM 中存储形状 (batch_size, n_heads, seq_len, seq_len) 的大型中间 attention 矩阵。相反，我们将在 HBM 中保存某些“activation checkpointing”，然后在反向传播过程中重计算部分前向传播，以获得计算梯度所需的其他激活。 FlashAttention-2 还存储 attention 分数 L 的 logsumexp，它将用于简化反向传播计算。 L 的表达式为：

$$ L_{i}=\log\Biggl(\sum_{j}\exp\bigl(S_{i j}\bigr)\Biggr) $$

在我们的最终 kernel 中，我们将以在线方式计算它，但最终结果应该是相同的。通过 tiling 和重计算的结合，我们的内存 IO 和峰值使用不再依赖于 sequence_length $ ^{2} $，因此我们可以使用更大的序列长度。

Operator fusion

最后，我们通过在单个 kernel 中执行所有操作来避免 attention 矩阵和其他中间激活的重复内存 IO，这称为算子或 kernel 融合。我们将为前向传播编写一个 Triton kernel，该 kernel 执行涉及 attention 的所有操作，并在 HBM 和 SRAM 之间传输有限的数据。算子融合部分是通过重计算实现的，因为我们可以避免通常的内存 IO，我们需要支付将每个中间激活存储到 HBM 的费用。

有关这些技术的更多直观信息，请查看 FlashAttention 论文 $ \boxed{T. Dao et al., 2022} $； $ \boxed{T. Dao, 2023} $。

使用重计算的反向传播

使用 $L$，我们可以进行适当的重计算并高效完成反向传播。在开始反向传播之前，我们先在全局内存中计算 $D = \text{rowsum}(O \circ dO)$（其中 $\circ$ 表示逐元素乘法）。由于 $PdP^{\top}=P(dOV^{\top})^{\top}=(PV)dO^{\top}=OdO^{\top}$，且对任意矩阵 $A$、$B$ 都有 $\textit{rowsum}(A \circ B)=\textit{diag}(AB^{\top})$，因此它等于 $\textit{rowsum}(P \circ dP)$。借助向量 $L$ 和 $D$，无需 softmax 即可计算反向传播。完整计算如下：

$$ \boldsymbol{S}=\boldsymbol{Q}\boldsymbol{K}^{\top}/\sqrt{d} $$

$$ P_{ij}=\exp\big(S_{ij}-L_{i}\big) $$

$$ d V=\boldsymbol{P}^{\top}d\boldsymbol{O} $$

$$ d P=d O V^{\top} $$

$$ d S_{i j}=P_{i j}\big(d P_{i j}-D_{i}\big) $$

$$ d Q=d S K/\sqrt{d} $$

$$ d\boldsymbol{K}=d\boldsymbol{S}^{\top}\boldsymbol{Q}/\sqrt{d} $$

我们可以看到，操作序列不需要我们在前向传播期间将 attention 分数 P 存储在 HBM 中 - 我们根据 $ \text{Equation 13} $ 和 $ \text{Equation 14} $ 中的激活 Q、K 和 L 重计算它们。

FlashAttention 前向传播的细节

现在我们已经对 FlashAttention-2 中使用的技术有了一个高层次的了解，我们将深入了解你将实现的 FA2 前向传播 kernel 的细节。为了避免从 HBM 读取和写入 attention 矩阵，我们希望使用分块，即独立于其他分块计算输出的每个分块。这要求我们能够计算 $P$ 的切片，理想情况下在两个维度上切片（对于查询和键）。

然而，当我们将 softmax 应用于$S$时，我们需要减少$S$的整行来计算 softmax 分母，这意味着我们无法直接计算 tile 中的$P$。 FlashAttention-2 使用在线 softmax 解决了这个问题。在下文中，我们将使用下标索引 $i$ 表示当前查询 tile，使用上标索引 $(j)$ 表示当前关键 tile。沿着查询维度的 tile 的大小将为 $B_{q}$，沿着关键维度的 tile 的大小将为 $B_{k}$。我们不会沿着隐藏维度 $d$ 进行 tiling。

我们还维护两个逐行更新的量：$m_i^{(j)} \in \mathbb{R}^{B_q}$ 和 $l_i^{(j)} \in \mathbb{R}^{B_q}$。其中 $m_i^{(j)}$ 是运行中的最大值，用于以数值稳定的方式计算 softmax；每处理一个新的 $S$ 行 tile（即 $j$ 增加）就更新一次。利用该运行最大值，可计算未归一化的 softmax 值（分子）$\widetilde{\mathbf{P}}_i^{(j)}=\exp(\mathbf{S}_{ij}-\mathbf{m}_i^{(j)})$。$l_i^{(j)}$ 是 softmax 分母的运行代理量，按 $l_i^{(j)}=\exp(m_i^{(j-1)}-m_i^{(j)})l_i^{(j-1)}+\operatorname{rowsum}(\widetilde{\mathbf{P}}_i^{(j)})$ 更新。最终写出输出时，使用处理完全部 key tile 后得到的 $l_i^{(T_k)}$ 完成归一化。算法 1 给出了 GPU 上的前向传播。

8

12

16

17

18

19

5.1 PyTorch 中的单节点分布式通信

让我们首先看一下 PyTorch 中的一个简单的分布式应用程序，其目标是生成四个随机整数张量并计算它们的总和。

在下面的分布式情况下，我们将生成四个工作进程，每个进程都会生成一个随机整数张量。为了对工作进程中的这些张量求和，我们将调用 all-reduce 集体通信操作，它将每个进程上的原始数据张量替换为 all-reduce 结果（即总和）。

import os
import torch
import torch.distributed as dist
import torch.multiprocessing as mp

def setup(rank, world_size):
    os.environ["MASTER_ADDR"] = "localhost"
    os.environ["MASTER_PORT"] = "29500"
    dist.init_process_group("gloo", rank=rank, world_size=world_size)

def distributed_demo(rank, world_size):
    setup(rank, world_size)
    data = torch.randint(0, 10, (3,))
    print(f"rank {rank} data (before all-reduce): {data}")
    dist.all_reduce(data, async_op=False)
    print(f"rank {rank} data (after all-reduce): {data}")

if __name__ == "__main__":
    world_size = 4
    mp.spawn(fn=distributed_demo, args=(world_size, ), nprocs=world_size, join=True)

5.2 分布式数据并行训练的朴素实现

现在我们已经了解了在 PyTorch 中编写分布式应用程序的基础知识，让我们构建分布式数据并行 (DDP) 训练的最小实现。

数据并行性将批次拆分到多个设备（例如 GPU）上，从而能够对不适合单个设备的大批量进行训练。例如，给定四个设备，每个设备可以处理最大批量大小为 32，数据并行训练将实现有效批量大小为 128。

以下是简单地进行分布式数据并行训练的步骤。最初，每个设备都会构建一个（随机初始化）模型。我们使用广播集体通信操作将模型参数从 rank 0 发送到所有其他 rank。在训练开始时，每个设备都保存模型参数和优化器状态的相同副本（例如 Adam 中累积的梯度统计数据）。

  1. 给定一个包含 n 个示例的批次，该批次被分片，每个设备接收 n/d 个不相交的示例（其中 d 是用于数据并行训练的设备数量）。 d 应该除以 n，否则某些 rank 会比其他 rank 做更多的工作，并且该步骤会受到最慢的瓶颈。

  2. 每个设备使用其模型参数的本地副本对其 $n/d$ 示例运行前向传播，并运行反向传播以计算梯度。请注意，此时，每个设备都保存根据其收到的 $n/d$ 示例计算出的梯度。

  3. 然后，我们使用 all-reduce 集体通信操作来平均不同设备上的梯度，因此每个设备都保存所有 n 个示例上的平均梯度。

  4. 接下来，每个设备运行优化器步骤来更新其参数副本 - 从优化器的角度来看，它只是优化本地模型。参数和优化器状态将在所有不同设备上保持同步，因为它们都从相同的初始模型和优化器状态开始，并为每次迭代使用相同的平均梯度。至此，我们已经完成了一次训练迭代，可以重复该过程。

我们将首先实现一个分布式数据并行包装器并对其进行 benchmarking，该包装器在单个参数张量在反向传播过程中准备就绪时异步地全部约简单个参数张量。以下提示可能有用：

后向钩子 要在反向传播中累积梯度后自动调用参数上的函数，可以使用 register_post_accumulate_grad_hook 函数。 $ ^{4} $

异步通信 所有 PyTorch 集体通信操作都支持同步 (async_op=False) 和异步执行 (async_op=True)。同步调用将阻塞，直到集体操作在 GPU 上排队。这并不意味着 CUDA 操作已完成，因为 CUDA 操作是异步的。话虽这么说，以后使用输出的函数调用将按预期运行。 $ ^{5} $ 相反，异步调用将返回分布式请求句柄 - 因此，当函数返回时，不能保证集体通信操作已在 GPU 上排队，更不用说完成了。要等待操作在 GPU 上排队（从而使输出可在以后的操作中使用），你可以在返回的通信句柄上调用 handle.wait()。

例如，以下两个示例通过同步或异步调用对张量列表中的每个张量进行 all-reduce：

# Synchronous, block until operation is queued on the GPU.
for tensor in tensors:
    dist.all_reduce(tensor, async_op=False)

# Asynchronous, return immediately after each call and
# wait on results at the end.
handles = []
for tensor in tensors:
    handle = dist.all_reduce(tensor, async_op=True)
    handles.append(handle)

# ...
# Possibly execute other commands that don't rely on the all_reduce results
# ...

# Ensure that all-reduce calls were queued and
# therefore other operations depending on the
# all-reduce output can be queued.
for handle in handles:
    handle.wait()
handles.clear()

6 优化器状态分片

7 完全分片数据并行

通过优化器状态分片和数据并行，我们能够在数据并行轴上分割优化器状态和激活。然而，我们的模型权重仍然是重复的——我们在每个 GPU 上存储它们的完整副本。

我们可以通过将数据并行（DP）轴转变为完全分片的数据并行轴（FSDP）来解决这个问题。使用 FSDP，每个 GPU 仅存储每个权重张量的自己的切片，但必须使用 all-gather 从其他 GPU 中提取切片以形成完整的权重张量，为前向或反向传播做好准备。

为了避免 GPU 计算等待通信完成，大多数 FSDP 实现都会在操作之前安排层的 all-gather，这意味着相关权重在需要之前就已准备好，从而防止通信阻塞计算。这使得权重分片通信远离关键路径，这意味着只要通信能够跟上计算的速度并且调度得当，它就没有成本。

有些层的内存和计算量足够小，因此传输的延迟开销不值得。你应该将这些层标记为不被 FSDP 分片。在我们的架构中，这主要是规范的情况。这给我们留下了嵌入层和每个线性层。

虽然需要在 FP32 中存储主权重（任何重复累加的值对精度都很敏感），但在 FP32 中不需要使用权重。在 mixed precision 中，我们总是在使用之前转换为低精度计算数据类型，因此我们甚至可以在传递权重之前进行转换以节省带宽。

8 分析并行策略

我们可以沿着更多的轴并行化我们的训练过程。一些常见的策略包括：

  • 数据并行性 (DP) — 批量数据分布在多个设备上，每个设备计算自己批次的梯度。然后对各个设备的梯度进行平均。

  • 完全分片数据并行（FSDP）——除了数据并行之外，我们还跨设备分割优化器状态、梯度和权重，以减少内存使用。然后，设备需要在向前和反向传播期间从其他设备收集权重分片。

  • 张量并行性 (TP) — 权重矩阵在输入或输出维度上进行分片。设备计算与其分片相对应的激活，然后跨设备减少或收集激活。

  • 管道并行性 (PP) — 模型被分层分成多个阶段，每个阶段在不同的设备上运行。

  • 专家并行 (EP) — 专家混合模型中的专家被分配到不同的设备上，每个设备为自己的专家计算输出。

在本节中，我们将在简化的设置中进行一些基本数学运算，以在并行策略之间进行选择并决定如何组合它们。首先，我们将重点关注 DP、FSDP、TP 及其组合。我们的方法是计算每个策略的通信成本，并将其与计算成本进行比较，这告诉我们在通信成本成为瓶颈之前我们可以扩展到多少设备。

对于 TPU/GPU 拓扑和并行策略的更详细处理，TPU Scaling Book（J. Austin 等人[6]）是一个很好的资源。有关更详细的管道并行讨论，请参阅超大规模剧本附录（H. Z. P. N. M. M. L. W. T. W. Nouamane Tazi Ferdinand Mom [7]）。这些书籍的其余部分还包含许多你可能会觉得有用的其他信息。

8.1 通信原语

我们的第一步是了解通信原语。在我们的简化设置中，假设我们有编号为 0, ..., $N-1$ 的 $N$ 设备，并且每对设备都通过链路连接。我们还假设每个设备都有 $W$ 出口（即传出）带宽；换句话说，每个设备可以以每秒 $W$ 字节的速率向另一个设备发送数据。我们如何实现聚集和减少？

实现 all-gather 操作的一种常见方法是环 all-gather。回想一下，在 all-gather 中，每个设备 $ i $ 以大小为 $ \frac{S}{N} $ 的块 $ x_i $ 开始，并以大小为 $ S $（以字节为单位）的整个 $ x = [x_0, ..., x_{N-1}] $ 结束。在 all-gather 环中，我们将设备排列成一个圆圈。在每个步骤中，每个设备将其当前块发送到其右侧的下一个设备，并存储从其左侧的设备接收到的块。重复此过程，每个设备将刚刚接收到的块传递到右侧，并从左侧接收新的块。经过 $ N-1 $ 步骤后，每个设备都拥有整个张量。

在我们的理想化设置中，每个设备在每个步骤中同时传输大小为 $ \frac{S}{N} $ 的块，出口带宽为 $ W $，并且有 $ N-1 $ 步骤，因此环 all-gather 需要 $ \frac{N-1}{N}\frac{S}{W} $ 秒。

接下来我们来分析一下环$ reduce_scatter $。在 reduce-scatter 中，每个设备$ i $都以大小为$ S $的完整张量$ \boldsymbol{x}^{(i)} $开始。然后，我们要计算归约结果 $ \boldsymbol{y} = \sum_{i=0}^{N-1} \boldsymbol{x}^{(i)} $，但每个设备 $ i $ 最终只有一个大小为 $ \frac{S}{N} $ 的块 $ y_i $。就像环聚集一样，我们首先将设备排列成一个圆圈。每个设备首先将其张量 $ \boldsymbol{x}^{(i)} $ 划分为 $ N $ 块 $ [x_0^{(i)}, ..., x_{N-1}^{(i)}] $，每个块的大小为 $ \frac{S}{N} $。然后，我们将像环 all-gather 一样传递块，除了在传递块之前，每个设备将其贡献添加到块（存储部分总和）。具体来说：

对于步骤 $t=1,\ldots,N-1$，设备 $i$ 执行以下操作：

  • 如果是$ t = 1 $，则初始化$ y \leftarrow x^{(i)} $，它存储到目前为止的部分和

  • 将块 $ y_{(i-t)\operatorname{mod}N} $ 发送到设备 $ (i+1)\operatorname{mod}N $

  • 从设备 $ (i-1)\operatorname{mod}N $ 接收块 $ z_{(i-t-1)\operatorname{mod}N} $

  • 更新你的部分和副本：$ y_{(i-t-1)\bmod N} \leftarrow y_{(i-t-1)\bmod N} + z_{(i-t-1)\bmod N} $

在 $N-1$ 步骤之后，设备 $i$ 就会获得块 $y_i$ 的全部总和，因此环 reduce-scatter 需要 $\frac{N-1}{N}\frac{S}{W}$ 秒，就像环 all-gather 一样。

最后，让我们实现 \textit{ring all-reduce}。在 all-reduce 中，每个设备 $ i $ 以大小为 $ S $ 的全张量 $ x^{(i)} $ 开始，并以归约 $ y = \sum_{i=0}^{N-1} x^{(i)} $ 结束。我们将把 all-reduce 实现为 \textit{ring reduce-scatter} 后跟 \textit{ring all-gather}，因此，ring all-reduce 需要 $ 2\frac{N-1}{N}\frac{S}{W} $ 秒。

8.2 分析数据并行

考虑到我们的通信原语，我们准备分析并行策略。我们将分析单个 FFN 层的并行化。回想一下，给定输入 x，我们的前向传播由以下公式给出：

$$ x_{1}=x W_{1} $$

$$ x_{2}=xW_{2} $$

$$ z=f(x_{1})*x_{2} $$

$$ y=z W_{3}, $$

其中，$ \boldsymbol{x} $ 的形状为 $ (B, D) $，$ W_1 $ 和 $ W_2 $ 的形状为 $ (D, D_{\mathrm{FF}}) $，$ W_3 $ 的形状为 $ (D_{\mathrm{FF}}, D) $。 $ f $ 是我们的元素激活函数（例如 SiLU），$ * $ 表示元素乘法。

显式写出反向传播也很有用。回想一下，给定形状为 $ (B, D) $ 的 $ \boldsymbol{d}\boldsymbol{y} $，反向传播由以下公式给出：

$$ d z=d y W_{3}^{\top} $$

$$ d x_{2}=d z*f(x_{1}) $$

$$ d x_{1}=d z*f^{\prime}(x_{1})*x_{2} $$

$$ d\boldsymbol{x}=d\boldsymbol{x}{1}\boldsymbol{W}{1}^{\top}+d\boldsymbol{x}{2}\boldsymbol{W}{2}^{\top} $$

$$ d W_{3}=z^{\top}d y $$

$$ d W_{2}=x^{\top}d x_{2} $$

$$ d W_{1}=x^{\top}d x_{1}, $$

其中 $ * $ 表示元素乘法。

回想一下，在与 $ N_{\mathrm{DP}} $ 设备的数据并行中，我们将输入 $ \pmb{x} $ 分片为大小为 $ \left(\frac{B}{N_{\mathrm{DP}}},\pmb{D}\right) $ 的分片 $ \pmb{x}^{(i)} $ 中。前向传播照常进行，没有任何集合，产生大小为 $ \left(\frac{B}{N_{\mathrm{DP}}},\pmb{D}\right) $ 的激活 $ \pmb{y}^{(i)} $。在

反向传播，像往常一样进行批量分片激活，设备 i 最终得到梯度

$$ d W_{3}^{(i)}=z^{(i)\top}d y^{(i)} $$

$$ d W_{2}^{(i)}=x^{(i)\top}d x_{2}^{(i)} $$

$$ d W_{1}^{(i)}=x^{(i)^{\top}}d x_{1}^{(i)}, $$

其中，我们不是对所有 $B$ 外积求和，而是仅对 $\frac{B}{N_{\mathrm{DP}}}$ 外积进行部分求和作为我们的输入份额。然后，我们需要跨设备进行 all-reduce 以获得完整梯度 $dW_3$、$dW_2$ 和 $dW_1$。

8.3 分析完全分片数据并行

接下来我们来分析一下 FSDP。回想一下，就像 DP 一样，FSDP 对输入和激活的批量维度进行分片。此外，为了节省内存，我们还对优化器状态、梯度和权重进行分片。我们可以沿任一维度对权重进行分片，在设备 i 上生成 $ W_1^{(i)} $、$ W_2^{(i)} $ 和 $ W_3^{(i)} $，每个尺寸为 $ \frac{DD_{FF}}{N_{FSDP}} $。

在前向传播中，我们将仅对批量分片输入进行数据并行前向传播。但要做到这一点，请记住，我们首先需要跨设备收集所有权重分片：

$$ \mathbf{W}_1=\operatorname{all\text{-}gather}\!\left(\left\{\mathbf{W}_1^{(i)}\right\}_{i=0}^{N_{\mathrm{FSDP}}-1}\right) \tag{34} $$

$$ \mathbf{W}_2=\operatorname{all\text{-}gather}\!\left(\left\{\mathbf{W}_2^{(i)}\right\}_{i=0}^{N_{\mathrm{FSDP}}-1}\right) \tag{35} $$

$$ \mathbf{W}_3=\operatorname{all\text{-}gather}\!\left(\left\{\mathbf{W}_3^{(i)}\right\}_{i=0}^{N_{\mathrm{FSDP}}-1}\right) \tag{36} $$

$$ \text{(do batch-sharded forward pass)} \tag{37} $$

请注意，当我们想要进行 all-gather 时，我们有一定的自由度：我们只需要在使用之前获得 all-gather 的权重，然后我们应该丢弃它以保持较低的内存成本。为简单起见，在本节中我们仅将三个 all-gather 一起列出。

与前向传播一样，在反向传播中，我们需要首先跨设备收集权重分片。然后我们可以进行数据并行反向传播，但我们不再需要进行 all-reduce，因为每个设备只需要其分片的梯度。因此，我们进行 reduce-scatter：

$$ \mathbf{W}_1=\operatorname{all\text{-}gather}\!\left(\left\{\mathbf{W}_1^{(i)}\right\}_{i=0}^{N_{\mathrm{FSDP}}-1}\right) \tag{38} $$

$$ \mathbf{W}_2=\operatorname{all\text{-}gather}\!\left(\left\{\mathbf{W}_2^{(i)}\right\}_{i=0}^{N_{\mathrm{FSDP}}-1}\right) \tag{39} $$

$$ \mathbf{W}_3=\operatorname{all\text{-}gather}\!\left(\left\{\mathbf{W}_3^{(i)}\right\}_{i=0}^{N_{\mathrm{FSDP}}-1}\right) \tag{40} $$

$$ \text{(do batch-sharded backward pass)} \tag{41} $$

$$ d\mathbf{W}_1^{(i)}=\operatorname{reduce\text{-}scatter}\!\left(\left\{d\mathbf{W}_1^{(i)}\right\}_{i=0}^{N_{\mathrm{FSDP}}-1}\right) \tag{42} $$

$$ d\mathbf{W}_2^{(i)}=\operatorname{reduce\text{-}scatter}\!\left(\left\{d\mathbf{W}_2^{(i)}\right\}_{i=0}^{N_{\mathrm{FSDP}}-1}\right) \tag{43} $$

$$ d\mathbf{W}_3^{(i)}=\operatorname{reduce\text{-}scatter}\!\left(\left\{d\mathbf{W}_3^{(i)}\right\}_{i=0}^{N_{\mathrm{FSDP}}-1}\right) \tag{44} $$

请注意，分片符号（上标 $ (i) $）已过载：reduce-scatter 的输入是完整权重的部分和，而输出是分片权重的完整和。

8.4 分析张量并行

在实践中，FSDP 通常与称为张量并行（TP）的并行策略相结合。在 TP 中，我们跨设备分割每个权重矩阵的输入或输出维度。输入维度分片通常称为“行并行”，而输出维度分片通常称为“列并行”。

具体来说，假设我们想要对形状为 $ (B, D) $ 的 $ \pmb{x} $ 和形状为 $ (D, D_{\mathrm{FF}}) $ 的 $ \pmb{W} $ 的 matmul 进行分片 $ \pmb{x}\pmb{W} $。在列并行中，我们有形状为 $ (D, \frac{D_{\mathrm{FF}}}{N_{\mathrm{TP}}}) $ 的分片 $ \pmb{W}^{(i)} $，并且我们有

$$ \mathbf{xW}=\operatorname{all\text{-}gather}\!\left(\left\{\mathbf{xW}^{(i)}\right\}_{i=0}^{N_{\mathrm{TP}}-1}\right) \tag{45} $$

另一方面，对于行并行，我们有形状为 $\left(\frac{D}{N_{\mathrm{TP}}},D_{\mathrm{FF}}\right)$ 的分片 $\mathbf{W}^{(i)}$，并且每个设备还在进行 matmul 之前将输入 $\mathbf{x}$ 缩小为形状为 $\left(B,\frac{D}{N_{\mathrm{TP}}}\right)$ 的切片 $\mathbf{x}^{(i)}$。那么，我们有

$$ \mathbf{xW}=\operatorname{all\text{-}reduce}\!\left(\left\{\mathbf{x}^{(i)}\mathbf{W}^{(i)}\right\}_{i=0}^{N_{\mathrm{TP}}-1}\right) \tag{46} $$

为了并行化我们的 FFN，我们将使用特定的张量并行配置，其中 $ W_1 $ 和 $ W_2 $ 是列并行（输出维度分片），而 $ W_3 $ 是行并行（输入维度分片）。由于行并行权重仅需要输入的一部分，因此此配置让我们可以跳过列并行权重之后的 all-gather。给定大小为 $ (B, D) $ 的输入 $ \pmb{x} $，该策略给出以下前向传播：

$$ \mathbf{x}_1^{(i)}=\mathbf{xW}_1^{(i)} \tag{47} $$

$$ \mathbf{x}_2^{(i)}=\mathbf{xW}_2^{(i)} \tag{48} $$

$$ \mathbf{z}^{(i)}=f\!\left(\mathbf{x}_1^{(i)}\right)\circ\mathbf{x}_2^{(i)} \tag{49} $$

$$ \mathbf{y}^{(i)}=\mathbf{z}^{(i)}\mathbf{W}_3^{(i)} \tag{50} $$

$$ \mathbf{y}=\operatorname{all\text{-}reduce}\!\left(\left\{\mathbf{y}^{(i)}\right\}_{i=0}^{N_{\mathrm{TP}}-1}\right) \tag{51} $$

其中 $ W_{1}^{(i)} $ 和 $ W_{2}^{(i)} $ 的形状为 $ (D, \frac{D_{\mathrm{FF}}}{N_{\mathrm{TP}}}) $，$ W_{3}^{(i)} $ 的形状为 $ \left(\frac{D_{\mathrm{FF}}}{N_{\mathrm{TP}}}, D\right) $。

8.5 二维并行（FSDP + TP）

我们终于准备好结合并行策略了！在本节中，我们将了解如何最佳地结合 FSDP 和 TP。提示：在前面的部分中，你应该已经发现你的批量大小和模型大小参数限制了你可以扩展到的设备数量，其中使所有内容变大可以让你继续扩展设备而不会遇到通信瓶颈。不幸的是，将批量大小扩展到某个点之后就会开始降低性能，因为梯度噪声显着缩小，从而失去了 SGD 的隐式正则化属性；这一点通常称为“临界批量大小”。缩放定律通常告诉我们我们希望模型有多大（这将是你在下一个任务中的工作！）。

在本节中，我们将考虑一种简化的设置，其中有人会向你提供所有问题参数（批量大小、模型大小、带宽、加速器速度）。你的工作将是选择可扩展到尽可能多的设备的 FSDP 和 TP 配置，同时保持计算限制而不是通信限制。

我们首先来了解一下 FSDP 与 TP 结合的机制。每个设备将具有 TP rank $ i = 0, ..., N_{\text{TP}} - 1 $ 和 FSDP rank $ j = 0, ..., N_{\text{FSDP}} - 1 $，形成总共 $ N = N_{\text{TP}} N_{\text{FSDP}} $ 设备的 2D 网格。继 TP 之后，我们将首先沿输出维度对 $ \mathbf{W}_1 $ 和 $ \mathbf{W}_2 $，进行分片，并沿输入维度对 $ \mathbf{W}_3 $。因此，我们必须在激活上插入 TP 风格的 all-reduce。接下来，应用 FSDP，我们将对输入的 batch 维度进行分片，并且我们还将沿着 TP 未共享的维度进一步对每个权重矩阵进行分片。然后，在进行 TP 式前向/反向传播之前，我们必须在权重上插入 FSDP 式 all-gather，并在 TP 式反向传播后在权重梯度上 reduce-scatter。

结果是每个设备 $(i,j)$ 都持有形状为 $\left(\frac{D}{N_{\mathrm{FSDP}}},\frac{D_{\mathrm{FF}}}{N_{\mathrm{TP}}}\right)$ 的权重分片 $W_1^{(i,j)}$ 和 $W_2^{(i,j)}$。以及形状为 $\left(\frac{D_{\mathrm{FF}}}{N_{\mathrm{TP}}},\frac{D}{N_{\mathrm{FSDP}}}\right)$ 的 $W_3^{(i,j)}$。然后，给定大小为 $\left(\frac{B}{N_{\mathrm{FSDP}}},D\right)$ 的批量分片输入 $\boldsymbol{x}^{(j)}$，我们可以将前向传播写出如下：

$$ \mathbf{W}_1^{(i)}=\operatorname{all\text{-}gather}\!\left(\left\{\mathbf{W}_1^{(i,j)}\right\}_{j=0}^{N_{\mathrm{FSDP}}-1}\right) \tag{52} $$

$$ \mathbf{W}_2^{(i)}=\operatorname{all\text{-}gather}\!\left(\left\{\mathbf{W}_2^{(i,j)}\right\}_{j=0}^{N_{\mathrm{FSDP}}-1}\right) \tag{53} $$

$$ \mathbf{W}_3^{(i)}=\operatorname{all\text{-}gather}\!\left(\left\{\mathbf{W}_3^{(i,j)}\right\}_{j=0}^{N_{\mathrm{FSDP}}-1}\right) \tag{54} $$

$$ \mathbf{x}_1^{(i,j)}=\mathbf{x}^{(j)}\mathbf{W}_1^{(i)} \tag{55} $$

$$ \mathbf{x}_2^{(i,j)}=\mathbf{x}^{(j)}\mathbf{W}_2^{(i)} \tag{56} $$

$$ \mathbf{z}^{(i,j)}=f\!\left(\mathbf{x}_1^{(i,j)}\right)\circ\mathbf{x}_2^{(i,j)} \tag{57} $$

$$ \mathbf{y}^{(i,j)}=\mathbf{z}^{(i,j)}\mathbf{W}_3^{(i)} \tag{58} $$

$$ \mathbf{y}^{(j)}=\operatorname{all\text{-}reduce}\!\left(\left\{\mathbf{y}^{(i,j)}\right\}_{i=0}^{N_{\mathrm{TP}}-1}\right) \tag{59} $$
